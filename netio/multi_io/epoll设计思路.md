1\. 数据结构与选取原因

epoll 在内核中的核心数据结构由两部分组成：红黑树与双向链表。



红黑树用于存储所有被监视的文件描述符及其关注的事件（兴趣列表）。双向链表（就绪列表）用于存放已经就绪的 fd。



选择红黑树而非其他查找结构的原因如下：



相较于哈希表：哈希表查询为 O(1)，但 epoll 在创建时无法预知需要监视的 fd 数量。若底层数组过小，大量 fd 会导致冲突退化；若数组过大，少量 fd 时又浪费内存。红黑树在 epoll\_create 时只需创建一个根节点，按需增长，空间效率更高。



相较于 B/B+ 树：B/B+ 树是多叉树，设计目标是降低树高以减少磁盘 I/O，适用于磁盘索引场景。epoll 工作在内存中，多叉结构带来的节点内二分查找与缓存不友好的问题，使其在内存索引场景下并不优于红黑树。



相较于跳表：跳表实现简单且并发性能较好，但需要维护多层索引，空间开销高于红黑树；且内核中红黑树已有成熟实现与广泛使用，复用的工程成本更低。



红黑树以 O(log n) 的插入、删除、查找复杂度，在时间与空间之间取得了适合 epoll 场景的平衡。就绪链表则保证了 epoll\_wait 只需处理已就绪的 fd，其开销与就绪数量成正比，而非与总监视数成正比。



2\. TCP 可读/可写的判断机制

epoll 本身不主动轮询 IO 状态，而是依赖内核协议栈的回调机制。



可读判断（连接 fd）

当 TCP 接收缓冲区从空变为非空（收到数据），或连接关闭（收到 FIN/RST）时，协议栈触发可读回调，进而调用 epoll 注册的 ep\_poll\_callback，将对应节点加入就绪链表。



可读判断（监听 fd）

监听 fd 的可读条件与连接 fd 不同。listen() 将 socket 置为监听状态后，内核为其维护半连接队列（SYN 队列）和全连接队列（accept 队列）。三次握手由内核独立完成：收到 SYN 创建半连接；收到第三次 ACK 后，连接从半连接队列移入全连接队列。当全连接队列从空变为非空时，监听 fd 即被视为可读。内核在 inet\_csk\_listen\_poll() 中的逻辑是：accept 队列不空则返回 EPOLLIN。此时 epoll 回调将监听 fd 加入就绪链表，epoll\_wait 返回后应用程序调用 accept() 取出连接。



可写判断

当 TCP 发送缓冲区从满变为有空闲空间时，协议栈触发可写回调，将 fd 置为就绪。连接初始建立时发送缓冲区为空，也会触发一次可写通知。



3\. 线程安全机制

epoll 的线程安全依赖两把锁，分别保护不同的数据结构：



自旋锁 ep->lock

保护就绪链表（rdllist）及与就绪状态相关的快速操作。ep\_poll\_callback 在将节点插入就绪链表时持有此锁，epoll\_wait 在取出节点时同样持锁。选择自旋锁的原因是：这些操作极短（仅链表指针操作），且 ep\_poll\_callback 可能运行在软中断上下文，不能睡眠，自旋锁是唯一选择。



互斥锁 ep->mtx

保护红黑树（兴趣列表）以及 epoll 实例的生命周期相关操作。epoll\_ctl 的添加、修改、删除操作，以及 epoll\_wait 的事件收集循环，均需持有此锁。选择互斥锁的原因是：这些操作可能涉及内存分配（如 ep\_insert 创建 epitem），或在等待事件时可能睡眠，自旋锁不可用于可睡眠上下文。



简言之：ep->lock 管就绪链表，ep->mtx 管红黑树与实例生命周期。这种分离使得回调路径（快速、不可睡眠）与控制路径（可能睡眠）互不阻塞，兼顾了正确性与性能。



4\. 水平触发与边缘触发的区别及实现

水平触发（LT，默认模式） ：只要 fd 仍处于就绪状态（如接收缓冲区还有数据、accept 队列非空），每次 epoll\_wait 都会返回该 fd。实现上，LT 模式在事件被取出后，若条件仍满足，节点会再次被加入就绪链表。



边缘触发（ET，需设置 EPOLLET） ：仅在 fd 状态发生变化时通知一次（如接收缓冲区从空变为非空、accept 队列从空变为非空）。实现上，ET 模式在事件被 epoll\_wait 取出后，节点从就绪链表移除，不会因条件仍满足而重新加入。只有新的状态变化（如又有新数据到达空缓冲区、又有新连接进入已清空的 accept 队列）才会再次触发回调。



ET 模式要求应用程序使用非阻塞 fd，并在收到通知后循环读写直到返回 EAGAIN，否则可能因遗漏事件导致连接挂起。LT 模式编程更简单，但可能产生更多系统调用。



5\. 核心函数详解

epoll\_create1(int flags)

创建一个 epoll 实例，返回其文件描述符。flags 可设为 EPOLL\_CLOEXEC，使 fd 在 exec 时自动关闭。与旧版 epoll\_create(size) 不同，epoll\_create1 去掉了已废弃的 size 参数，内核动态管理内部结构大小。



epoll\_ctl(int epfd, int op, int fd, struct epoll\_event \*event)

控制 epoll 实例的兴趣列表。op 取值：



EPOLL\_CTL\_ADD：将 fd 注册到 epoll 实例，关联关注事件（如 EPOLLIN、EPOLLOUT、EPOLLET）。



EPOLL\_CTL\_MOD：修改已注册 fd 的关注事件。



EPOLL\_CTL\_DEL：将 fd 从 epoll 实例中移除。



epoll\_wait(int epfd, struct epoll\_event \*events, int maxevents, int timeout)

等待 epoll 实例上的 IO 事件。阻塞直到至少一个 fd 就绪、被信号中断、或超时（timeout 毫秒，-1 永久阻塞）。返回就绪 fd 数量，事件信息填入 events 数组，最多返回 maxevents 个。



ep\_poll\_callback（内核回调，非用户 API）

epoll 事件驱动的关键内部函数。当被监视的 fd 上有事件发生（数据到达、缓冲区腾出空间、accept 队列非空等）时，内核等待队列调用此回调。它负责将对应的 epitem 插入就绪链表，并唤醒正在 epoll\_wait 中睡眠的线程。该回调运行在软中断或进程上下文，持有 ep->lock 以保证并发安全。
